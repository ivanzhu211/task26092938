# bottleneck — 审批瓶颈分析库

Go 库，由上层直接调用。导入一份冻结的审批台账后建立只读统计快照（保存在进程内存），
随后按提交最终完成时间窗口反复查询各阶段停留统计与瓶颈阶段。

## 能力

- `BuildSnapshot(submissions, stageCount)`：建立只读统计快照。`stageCount ∈ [1, 10]`。
- `snapshot.Query(start, end)`：按完成时间窗口 `[start, end)`（含起点、不含终点）查询，
  返回各阶段样本数、平均停留、精确中位数，以及中位数最大的瓶颈阶段（并列全部返回）。

## 统计口径

- 仅 `StatusApproved` / `StatusRejected` 提交参与统计；草稿、待审批、退回修改整体排除。
- 窗口按提交最终完成时间筛选；选中提交的全部阶段历史（含窗口开始前的停留）完整计入。
- 每份提交在每个实际到达的阶段贡献一个样本，样本值为各轮次停留秒数之和；
  未到达的阶段不补零，0 秒停留仍计样本。
- 偶数样本的中位数为中央两值的算术平均（浮点精确表示，不取整）。

## 实现要点

- 每个阶段维护按完成时间排序的样本数组、前缀和（O(1) 求平均），
  以及建在样本值上的归并排序树（merge sort tree），
  支持 O(log²n) 的区间第 k 小查询，从而快速求得任意窗口的精确中位数。
- 单线程调用；快照建立后只读，无持久化与在线增量更新。

## 测试

```sh
go test ./...
```

正确性测试覆盖验收用例（返工聚合 2+8/4/6 → 样本3、均值20/3、中位数6；
边界完成时间只进后一个窗口且历史完整计入），并与独立暴力实现做随机对照。

## 规模实测（Apple Silicon，Go 1.27）

20 万份提交、合计 200 万次阶段停留、10 个阶段、1 万次不同宽度窗口
（其中一半命中全部提交的 20%~80%）：

| 指标 | 实测 | 上限 |
| --- | --- | --- |
| 建立快照 | ~0.47 s | 30 s |
| 1 万次查询总耗时 | ~0.73 s | 10 s |
| 进程峰值内存（含输入台账） | ~377 MiB | 768 MiB |

由 `TestPerformanceAtScale`（`perf_test.go`）自动断言以上三项上限。
