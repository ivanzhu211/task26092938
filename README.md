# bottleneck — 审批瓶颈分析库

由一份冻结的审批台账建立**只读统计快照**（进程内存），并支持按提交**最终完成时间窗口**反复查询各阶段统计与瓶颈阶段。纯 Go 实现，无外部依赖，单线程调用。

## 用法

```go
stages := []string{"初审", "复审", "终审"} // 表单版本的阶段，最多 10 个
snap := bottleneck.BuildSnapshot("v1", stages, submissions)
res := snap.Query(windowStart, windowEnd) // [start, end)，UTC 整数秒
// res.Stages:      各阶段样本数 / 平均停留 / 精确中位数（无样本的阶段不出现）
// res.Bottlenecks: 中位数最大的阶段，并列时全部返回
```

## 统计口径

- 仅 `StatusApproved` / `StatusRejected` 参与统计；草稿、待审批、退回修改整体排除。
- 窗口按最终完成时间筛选，含起点不含终点；选中提交的全部阶段历史（含窗口开始前的停留）完整计入。
- 每份提交在每个实际到达的阶段贡献一个样本，样本值 = 该阶段所有轮次停留秒数之和；未到达不补零，0 秒停留仍计样本。
- 偶数样本中位数为中央两值的算术平均（float64 精确表示，如 3.5）。

## 实现要点

- 构建：按提交聚合各阶段停留 → 每阶段按完成时间排序，建立前缀和（O(1) 求样本数与平均值）与**小波树**（O(log σ) 区间第 k 小，用于精确中位数）。
- 查询：每阶段两次二分定位窗口，中位数经小波树两次 kth 查询；1 万次查询无需排序或扫描原始数据。

## 性能记录（Apple Silicon，Go 1.27.1，规模：20 万提交 / 200 万停留 / 10 阶段）

| 指标 | 实测 | 上限 |
|---|---|---|
| 快照构建耗时 | ~0.77 s | 30 s |
| 1 万次窗口查询总耗时 | ~0.12 s | 10 s |
| 进程峰值内存（含输入台账） | ~320 MiB | 768 MiB |
